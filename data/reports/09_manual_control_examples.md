# Этап 9 — Контрольные примеры от пользователя

Пользователь привёл два конкретных кейса в `data/final/socialnyy_ready.html`, чтобы проверить, что audit действительно строгий и проверяет существование anchor, а не просто наличие `<a>` тега.

## Контрольный пример №1 — Социальный кодекс, статья 246, пункт 5

**Текст в HTML (ожидаемая ссылка):**
```
"пунктом 5 статьи 823 Налогового кодекса Республики Казахстан"
```

| Этап | Значение |
|---|---|
| Найденный текст | `пунктом 5 статьи 823 Налогового кодекса Республики Казахстан` |
| **Текущий href до исправления** | `http://85.202.192.66:9096/rus/docs/K2500000214#z13008` |
| Существовал ли target anchor `z13008` до исправления? | **ДА**, но `z13008` — это заголовок ст.823 («Статья 823. Порядок исчисления, уплаты единого платежа…»), а не пункт 5. То есть ссылка вела на правильную **статью**, но не на её **пункт 5** — фактически в начало статьи. Пользователь воспринимает это как «Not Found / неправильное место». |
| **Корень проблемы** | Скрипт `10_cross_code_refs.py` строил cross-code href только по `article_map_nalog["823"] → z13008`, не учитывая, что в фразе указан пункт 5. У него не было доступа к `subpoint_map` целевого кодекса. Кроме того, скрипт `07_add_subpoint_anchors.py` не записывал в `subpoint_map_nalog.json` ключ `"823_5"` — он строил мapping только для подпунктов (3-уровневый ключ `art_punkt_subp`), но не для пунктов (2-уровневый ключ `art_punkt`). |
| **Исправление** | (a) В `07_add_subpoint_anchors.py` добавлен инжект 2-уровневого ключа `art_punkt` в `subpoint_map`. Для ст.823 п.5: в источнике у этого пункта уже есть `<p id="z13013">`, поэтому `subpoint_map_nalog["823_5"] = "z13013"` (используем существующий id). (b) В `10_cross_code_refs.py` функция `make_link` теперь принимает `punkt_num/subp_num` и сначала смотрит в `subpoint_map[target]["{N}_{P}"]`, и только потом fallback'ит к article_map. |
| **Правильный href** | `http://85.202.192.66:9096/rus/docs/K2500000214#z13013` |
| Существует ли target anchor `z13013` после исправления? | **ДА** — `<p id="z13013">` в `data/final/nalog_ready.html` (это пункт 5 ст.823, начинается с «5. Налоговые агенты производят уплату социальных отчислений…»). |
| **Статус** | ✅ **PASS** (linked to existing anchor, exact point match) |

**Команда для проверки:**
```bash
grep -o 'href="[^"]*#z13013"' data/final/nalog_ready.html | head -1
# → href="...K2500000214#z13013"  (anchor определён в nalog_ready.html)

grep -o 'id="z13013"' data/final/nalog_ready.html | head -1
# → id="z13013"
```

## Контрольный пример №2 — Социальный кодекс, статья 246, пункт 8

**Текст в HTML:**
```
"…в соответствии с частью первой пункта 1 статьи 256 настоящего Кодекса…"
```
Кликабельная часть: «пункта 1» (отдельной ссылкой) + «статьи 256» (отдельной ссылкой).

| Этап | Значение |
|---|---|
| Найденный текст | `<a href="…/K2300000224#z3264">пункта 1</a> <a href="…/K2300000224#z3263">статьи 256</a> настоящего Кодекса` |
| **Текущий href до исправления** | `https://adilet.zan.kz/rus/docs/K2300000224#z3264` |
| Существовал ли target anchor `z3264` до исправления? | **НЕТ** — `z3264` отсутствует и в нашем `data/final/socialnyy_ready.html`, и в исходном `data/source/socialnyy.html` (0 occurrences). Это **унаследованный битый якорь с adilet.zan.kz** — у них же в исходном HTML стоит `<a href="…#z3264">пункта 1</a>`, но id `z3264` нигде не определён даже у них. Браузер при клике скроллит в начало документа. |
| **Корень проблемы** | (a) Битая ссылка пришла **из исходного HTML adilet.zan.kz** — наш пайплайн её не создавал, он просто оставил её как есть (внутри уже существующего `<a>`). (b) Скрипт 07 не создавал свой anchor для пункта 1 статьи 256, потому что у `<p>` (первый абзац пункта 1) НЕ было `id` — adilet проставил id только со второго абзаца (`<p id="z3265">`). |
| **Исправление** | (a) Скрипт `07_add_subpoint_anchors.py` теперь инжектирует синтетический `<a id="z<art>_p<pt>" name="z<art>_p<pt>">` в начало `<p>`, если у него нет своего id. Для ст.256 п.1 синтезирован `z256_p1` (присутствует в `socialnyy_ready.html` 2 раза — в исходном пункте 1 и в его перекрёстном использовании). (b) Новый скрипт `15_fix_broken_anchors.py` находит ссылки с битыми anchor-ами (`<a href="…#zXXX">` где `zXXX` не существует в локальном `<code>_ready.html`) и переписывает href: для текста «пункта N» он смотрит на следующий `<a>статьи M</a>`, берёт `subpoint_map[target_code]["M_N"]` (теперь там есть `256_1 → z256_p1`) и подставляет правильный anchor. |
| **Правильный href** | `http://85.202.192.66:9096/rus/docs/K2300000224#z256_p1` |
| Существует ли target anchor `z256_p1` после исправления? | **ДА** — `<a id="z256_p1" name="z256_p1">` встречается в `data/final/socialnyy_ready.html` 2 раза. |
| **Статус** | ✅ **PASS** |

**Команда для проверки:**
```bash
grep -o 'href="[^"]*#z256_p1"' data/final/socialnyy_ready.html | head -1
# → href="...K2300000224#z256_p1"

grep -o 'id="z256_p1"' data/final/socialnyy_ready.html
# → id="z256_p1"  (anchor существует)

grep -c 'id="z3264"' data/final/socialnyy_ready.html
# → 0   (битого anchor больше нет ни как id, ни как target)
```

## Обновление логики audit

Был создан строгий audit `scripts/debug/audit_anchors_strict.py`, который для **каждого** `<a href>` в каждом из 12 HTML-файлов проверяет:

1. **href не пустой** — иначе `FAIL_EMPTY_OR_HASH`.
2. **href не "#"** — иначе `FAIL_EMPTY_OR_HASH`.
3. **Если href внутренний** (просто `#zN`) — целевой `id="zN"` или `name="zN"` обязан существовать в этом же HTML. Иначе `FAIL_BROKEN_INTERNAL_ANCHOR`.
4. **Если href cross-code на один из 12 локальных кодексов** (по doc_id) — целевой anchor обязан существовать в соответствующем локальном `<target_code>_ready.html`. Иначе `FAIL_BROKEN_EXTERNAL_ANCHOR`.
5. **Если href на корень документа без anchor** (`…/rus/docs/K…`) — всегда PASS.
6. **Если href на НПА вне 12 кодексов** (например, Закон «О микрофинансовой деятельности» — у нас локально нет соответствующего ready.html) — `PASS_EXTERNAL_UNVERIFIED` (страховочный путь без проверки anchor).
7. **Если href на навигацию сайта** (javascript:, /rus/advertising, /kaz/docs, и т.п.) — `PASS_OFFSITE_OR_NAV`.

Сам файл audit: `scripts/debug/audit_anchors_strict.py`.
Результат: `data/reports/08_anchor_validation.json` + `.md`.

Стратегия исправления:

## Изменения в пайплайне

Добавлены/обновлены:
1. **`scripts/07_add_subpoint_anchors.py`** — инжектирует синтетический anchor `z<art>_p<pt>` для каждого пункта, у которого в источнике нет id. Записывает в subpoint_map 2-уровневые ключи `{art}_{pt}` дополнительно к 3-уровневым `{art}_{pt}_{subp}`.
2. **`scripts/10_cross_code_refs.py`** — `make_link` теперь принимает `punkt_num`/`subp_num` и использует `subpoint_map` целевого кодекса для построения точного anchor cross-code ссылки. Если точного anchor нет — ссылается на корень документа (а не на «угадываемый» anchor).
3. **`scripts/15_fix_broken_anchors.py`** — **новый** пост-обработчик: проверяет каждую `<a href>` в ready HTML, и для битых ссылок переписывает href на существующий anchor (через контекстный анализ соседних ссылок) или на корень документа.
4. **`scripts/debug/audit_anchors_strict.py`** — **новый** строгий audit, который проверяет существование каждого targeted anchor в локальных HTML-файлах.
