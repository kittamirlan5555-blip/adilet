# COVER — пакет структурированного корпуса (25 документов)

Каждый файл `{документ}.jsonl` — строки-чанки: `id`, `text` (текст единицы с
заголовочным префиксом `[КОД | Статья N. Название | пункт M]`), `meta`
(см. QUALITY.md).

## Идентификатор чанка

**`id` = `meta.hier_id`** — единый машинный адрес (решение ревью 2026-06-12).
Разбор: `APPKR2G8ST58SP1` = АППК, раздел 2, глава 8, статья 58, подпункт 1);
при повторе адреса — суффикс `~N`. Поле `meta.legacy_id` — СЛУЖЕБНОЕ: прежний
человекочитаемый id (`appk_ст58_пп1`) для трассировки со старыми выгрузками. Поле `meta.hier_id` — машинный иерархический адрес чанка; при суффиксе `~N` его номер продублирован в `meta.hier_dup_seq`, а `meta.split_from` указывает родительский чанк разбиения.

## Грамматика hier_id

`CODE (CHn)? (Rn)? (Gn)? (PGn)? STn (Pn)? (SPn)?` — сегменты слева направо:

| сегмент | значение | пример |
|---|---|---|
| CODE | короткий код документа (реестр ниже) | `UK`, `BK`, `NT` |
| CHn | часть (Общая/Особенная — только УК, УПК, КоАП) | `CH1` |
| Rn | раздел | `R1` |
| Gn | глава | `G4` |
| PGn | параграф | `PG2` |
| STn | статья | `ST1` |
| Pn | пункт / часть статьи | `P1` |
| SPn | подпункт | `SP3` |
| ~N | суффикс-дедупликатор: повторная единица с тем же адресом (продолжения после сносок и т.п.); базовый адрес — часть до `~` | `BKR1G1ST5SP1~2` |

Дефисный номер `n-m` возможен у ЛЮБОГО сегмента, не только у статьи: `G12-1` (глава 12-1), `ST90-1`, `P3-1`, `SP14-1` — живые примеры: `APPKR3G12-1ST90-1P1`, `APPKR1G1ST4P1SP14-1`.

## Разбор двух примеров

1. `UKCH1R1ST1P1` (UK, Уголовный кодекс): часть CH1, раздел 1, статья 1, часть 1 — «[УК | Статья 1. Уголовное законодательство Республики Казахстан …»

2. `NTR1G1ST1P1` (NT, Закон «О нотариате»): раздел 1, глава 1, статья 1, пункт 1 — «[НТ | Статья 1. Нотариат в Республике Казахстан | пункт 1]…»

## Префикс `[intro]`

Чанк с `text`, начинающимся с `[intro]`, — вводный абзац единицы ДО её первого пункта/подпункта (шапка статьи-перечня и т.п.). Пример (bezhenci, `BEZST1`):

```
[intro]
В настоящем Законе используются следующие основные понятия:
```

Внутри intro-чанка всегда присутствует и обычный заголовок `[КОД | Статья N. …]` — чанк самоидентифицирован.
