# Сабчанкинг больших статей (вектор-слой, Фаза B)

Источник «больших»: готового набора 100 в репо нет -> взяты **top-100 статей по длине тела** (символы get_text). **Порог «большой» = 9498 символов** (длина 100-й статьи; самая длинная — 47748).

Чанков всего: **400** = 100 parent + 300 сабчанков.
Сабчанков на статью: 3→100 статей

Поля чанка: chunk_id, parent_id, article_no, text, char_len, order (+ doc_id, code, anchor, uid, kind; summary — на parent, Фаза C).
chunk_id parent = якорь статьи zX (НЕ изменён); сабчанк = zX_1/_2/_3 (additive). Глобальный ключ — uid = `{code}_{zX}` (zX не уникален между документами).

## Реконструкция

Сабчанки реконструируют **ТЕЛО** статьи: склейка `text` сабчанков по `order` равна телу статьи — **тело сходится 100/100, потерь контента 0**. Заголовок «Статья N. Название» в сабчанки НЕ дублируется (by-design); он хранится в `parent.text` (целиком) и в поле `meta.article_title`. Посимвольное совпадение склейки со ВСЕМ `parent.text` — **14/100** (статьи без отдельной строки-заголовка); у остальных **86/100** разница ровно на строку заголовка. Контент не теряется.
