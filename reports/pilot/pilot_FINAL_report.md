# ПИЛОТ-100 — итоговый отчёт

Ветка `pilot-100` (от `audit`). 100 случайных реальных законов РК (Z-префикс), собранных
честным BFS-обходом adilet, прогнаны через **структуру + ссылки + чанки** (без вектор-слоя).

Все цифры ниже — из **реальных артефактов на диске** (не из эвристических колонок драйвера).
Скрипты аудита: `pilot/verify_pilot.py`, `pilot/spotcheck.py`.

## 5. Спот-чек (независимо из сырого HTML, §6 — гейт слеп)

5 случайных DONE + 2 материальных закона для контраста:

- **text-invariance** (линковка не меняет видимый текст): **86/96** байт-в-байт.
- **nested `<a>` = 0, висячие `#z` = 0** по всем проверенным.
- **Гейт (69/64) пропускает 2 класса реальных дефектов** на поправках:
  1. **Escaped-anchor: 9/96 доков, 11 случаев** — ссылка отрендерилась как ЛИТЕРАЛЬНЫЙ текст
     `<a href="…">…</a>` (линкер вставил `<a>` внутрь цитируемого названия акта, потом шаг
     финализации это заэкранировал). Все 9 — GREEN у гейта.
  2. **Пустой `href=""`: 1 док** (Z2000000347, «подпункт 40-1)») — битая ссылка; гейт счёл её
     «chrome», т.к. контент поправки висит ВНЕ `div[data-type]`, а эвристика гейта «вне
     data-type = chrome».
- Остаточный chrome adilet (`href="#"`: Избранное/Обратная связь/тел.) остаётся в пилотных
  `_ready` (кураторские кодексы его вычищают) — косметика, не дефект ссылок.

Материальные законы (Z980000339_, Z1600000486 и др.) спот-чек проходят чисто.

## 8. Вывод одной строкой

Пайплайн **корректно обрабатывает материальные законы (12/12 чисто)**, но **не рассчитан на
законы-поправки — доминирующий формат Z-актов (88/100)**: они либо дают пустую структуру
(43), либо мусорные чанки-цитаты (42), либо падают (4). Драйверные DONE/GREEN это маскируют —
верить только независимому аудиту из файлов.
