## Корневые причины (Root causes)

### RC1 — `01_build_article_map.py` пропускает статьи без `<a name>`/`id` (regression-prone)

**Симптом:** В `data/maps/article_map_<code>.json` отсутствуют некоторые ключи (например, КоАП ст.59, ст.8). Из-за этого `02_fix_internal_links.py` не может построить ссылку «статьёй 59 настоящего Кодекса».

**Подтверждено:** В источнике `data/source/koap.html` ст.59 имеет структуру `<p><b>Статья 59. ...</b></p>` БЕЗ предшествующего `<a name="zN">` и БЕЗ `id`. Все 3 эвристики скрипта 01 промахиваются.

**Худший побочный эффект:** В готовом `koap_ready.html` сам заголовок «Статья 59…» **испорчен**:
```
<a href=".../K1400000235#z18">Статья 5</a>9. Возмещение вреда…
```
Регулярка `ARTICLE_PATTERN` («стать(я|и|ей)\s+(\d+)») в скрипте 02 жадно нашла «Статья 5» внутри «Статья 59», взяла anchor ст.5 и обернула «Статья 5» в ссылку. Цифра «9» осталась снаружи. Результат — **тот самый ARTICLE_TITLE_NOT_BOLD/«статья 115 не выделена»** из фото_9 Анары (АППК) и сообщения «УПК кривой».

**Затронуто:** КоАП, УПК, АППК, Уголовный, Гражданский, Земельный, Налоговый — везде, где есть заголовки статей без явного `<a name>` или `id`.

**Решение:**
1. **Расширить `01_build_article_map.py`** — добавить эвристику для случаев `<p><b>Статья N. …</b></p>` без id/name: синтезировать новый anchor (например `art<N>`) и записать в карту. Соответственно, перед заголовком вставить `<a id="art<N>" name="art<N>"></a>` (это делает скрипт 07 или новый шаг 01b).
2. **Скрипт 02_fix_internal_links.py: блокировать ARTICLE_PATTERN внутри заголовков статей** (внутри `<b>` или `<h3>`). Уже частично реализовано (`is_article_heading`), но не работает для КоАП-структуры `<p><b>…</b></p>`. Усилить проверку: если ARTICLE_PATTERN захватывает первое слово «Статья» в текстовом узле, это заголовок и линковать нельзя.
3. **Скрипт 02: ужесточить ARTICLE_PATTERN** — требовать, чтобы после числа НЕ шла цифра без разделителя. Т.е. «Статья 5» должно матчиться, только если следующий символ — пробел/точка/etc, а не цифра. Сейчас есть lookahead `(?!\s*\.(?:\s+|\s*[А-ЯЁA-Z]))`, но он не запрещает «Статья 5» → 9. Нужен явный `\b` или `(?!\d)`.

**Файлы:** `scripts/01_build_article_map.py`, `scripts/02_fix_internal_links.py`.

**Риск:** Изменение ARTICLE_PATTERN может слегка изменить распознание граничных случаев. Нужны regression-проверки (Этап 7).

### RC2 — Internal self-ref не линкуется (главное замечание Анары)

40 случаев FAIL_NOT_LINKED с типом `INTERNAL_LINK_MISSING_SELFREF` — фрагменты типа `«пунктом 1 настоящей статьи»`, `«частью первой настоящего пункта»`, `«параграфом 3 раздела 6 настоящего Кодекса»` НЕ оборачиваются в `<a>`.

Скрипт 02 уже содержит ряд паттернов для self-ref (`SELF_PART_PATTERN`, `SELF_PUNKT_PATTERN`, `SELF_MULTI_PUNKT_PATTERN`, `SAME_PART_SUBP_PATTERN`, `SAME_PUNKT_SUBP_PATTERN`). Они срабатывают только если передан `current_article` и `part_anchor_map`. Однако:
- `current_article` определяется внутри одной обработки HTML-параграфа: для текста внутри пункта нужно знать номер ОБЕЕЙ — статьи **и** пункта/части. Если контекст «теряется» (например, пункт 5 ст.245 находится в отдельном `<p>` далеко от заголовка статьи), `current_part` отсутствует, и `SAME_PART_SUBP_PATTERN` / `SAME_PUNKT_SUBP_PATTERN` не сработают.
- Паттерн «раздела 6 настоящего Кодекса» и «параграфом 3 раздела 6 настоящего Кодекса» вообще не покрыт (нет SECTION_PATTERN / PARAGRAPH_PATTERN).
- Паттерн «частью первой настоящей статьи», «частью второй настоящей статьи» (написание словом, не цифрой) не покрыт.

**Решение:**
1. Добавить новый паттерн **SELF_SECTION_PATTERN**: `«раздел(а|ом|у|е)?\s+N\s+настоящего\s+Кодекса»`. Требует subpoint_map либо section_map (TBD); скорее всего нужно расширить article_map либо создать новый `section_map_<code>.json`.
2. Добавить новый паттерн **SELF_PARAGRAPH_PATTERN**: `«параграф(?:ом|а)\s+N\s+(?:раздела\s+M\s+)?настоящего\s+Кодекса»`.
3. Добавить паттерн для **«частью первой/второй/третьей … настоящей статьи»** (словесные числительные).
4. Гарантировать, что `current_article` / `current_part` устанавливается корректно для каждого `<p>` (по контексту предыдущего «Статья N.» заголовка). Это уже есть, но нужно проверить, что точка обработки текстовых узлов правильно «считает» текущий контекст.

**Файлы:** `scripts/02_fix_internal_links.py`. Возможно, расширение `scripts/07_add_subpoint_anchors.py` для генерации anchors для разделов и параграфов.

**Риск:** Низкий — новые паттерны добавляют точечную обработку, не ломая существующие.

### RC3 — Внешние НПА: 14 FAIL_NOT_LINKED + некоторые FAIL_NOT_FOUND

14 случаев, где Анара хочет ссылку на внешний закон/кодекс, а текст в HTML есть, но без ссылки.

Скрипт 03 ищет вхождения фраз из `config/npa_mapping.json`. Если фразы нет в маппинге — ссылка не строится. Анализ FAIL показывает, что многие фразы в `socialnyy_*.docx`, `predprinimatel_*.docx`, `koap_*.docx` имеют немного другую форму, чем в маппинге, или вообще отсутствуют. Конкретные пропуски (примеры):
- «Закон Республики Казахстан "Об охранной деятельности"» — есть в маппинге, но в каких-то местах форма падежа другая;
- «Закон Республики Казахстан "О Фонде компенсации потерпевшим"» — есть.
- Возможные новые формы: «об инновационном кластере "Астана Хаб"» (с кавычками).
- «банковским законодательством Республики Казахстан» — нужно добавить.

**Решение:**
1. Доработать `config/npa_mapping.json`: добавить недостающие падежные формы.
2. По итогам аудита (`03_anara_current_state_audit.json`, FAIL_NOT_LINKED + EXTERNAL_*) собрать список конкретных фраз и приписать в маппинг.
3. Скрипт 03 уже работает по принципу подстроки, добавление новых ключей — безопасное.

**Файлы:** `config/npa_mapping.json`.

**Риск:** Минимальный — лишь расширение словаря.

### RC4 — TOO_MUCH_TEXT_LINKED / `:target` подсветка слишком большой

Анара жалуется на фото 5/7/8/10 (соц/земельный/АППК/гражд): «много выделенных», «настоящего/настоящим в желтом».

Это **НЕ** проблема ссылки — это проблема CSS+JS подсветки в `06_finalize.py`. JS добавляет класс `highlight-target` родительскому `<p>` (или ближайшему block-tag) при срабатывании `:target`. В результате весь параграф (десятки строк) загорается жёлтым.

**Решение:**
1. Изменить логику highlight: вместо подсветки родительского блока — подсветить только сам якорь (`<a>` или новый `<span>` вокруг места).
2. Альтернативно: уменьшить визуальный контраст (`background-color: rgba(255,255,140,0.4)`) — тогда даже большая зона не выглядит «слишком много».
3. Скриптом 07 анкоры пунктов/подпунктов уже ставятся в начале текста пункта (`<p id="z..._N">`). Можно изменить логику: при `:target` подсветить только первое ПРЕДЛОЖЕНИЕ или первые ~120 символов после якоря.

Самое простое — снизить контраст фона до приглушенного жёлтого + добавить тонкий цветной бордер сбоку. Это устранит ощущение «много выделенных». Это «UX» правка.

**Файлы:** `scripts/06_finalize.py`.

**Риск:** Низкий — стилизация.

### RC5 — ARTICLE_TITLE_NOT_BOLD (ст.115 АППК и аналоги)

В `appk_ready.html` ст.115 имеет HTML:
```
<p><b></a><a id="z1012" name="z1012"></a>Статья 115. …</b></p>
```
Лишний `</a>` ломает `<b>` в браузере (по факту — могут варьироваться парсеры).

**Корень:** Скрипт 13_cleanup_html.py разворачивает вложенные `<a>` и оставляет «осиротевшие» `</a>`. Либо предыдущий шаг (02/07) создаёт некорректный HTML, а 13 не убирает мусор полностью.

**Решение:**
1. В `13_cleanup_html.py` укрепить нормализацию: убирать ВСЕ orphan `</a>` и `<a>` без закрытия. Использовать lxml's `etree.tostring(parsed)` чтобы вывести валидную структуру.
2. Дополнительно, в самом скрипте 02 не создавать ситуации, в которых внешняя обёртка ломается. Конкретно — не оборачивать «Статья 5» внутри заголовка «Статья 59. ...» (это RC1).

**Файлы:** `scripts/13_cleanup_html.py` + RC1 (косвенно).

### RC6 — FAIL_NOT_FOUND: 20 случаев

Это случаи, где ни один ключевой фрагмент из docx Анары не нашёлся в текущем HTML.

Возможные причины:
1. Опечатка в docx у Анары: например, `predprinimatel_002` — «пункт 3 **стсатья** 35». Реестр это пропускает.
2. Разные формулировки: docx «Закон РК Об …», HTML «закона Республики Казахстан "Об …"».
3. Замечание относится к статье, которой нет в этом HTML (например, она оказалась в составе другой статьи или это «пункт 3» без указания статьи).
4. Текст в docx сжат и не точно соответствует HTML.

**Решение:** Список 20 — точечно разобрать вручную (manual review). Не системная проблема.

**Файлы:** Создать `data/reports/04b_manual_review.md` с раскрытием каждого из 20 случаев и пометками (закрыто / открыто / ложь).

## Что НЕ нужно делать

- **Не патчить готовые HTML напрямую.** Все исправления — в скриптах/маппингах/overrides.
- **Не убирать существующие рабочие ссылки.** Особенно при правках ARTICLE_PATTERN.
- **Не создавать nested `<a>`.** Это уже было багом (15.04).
- **Не оставлять href="" или href="#".** Скрипт audit уже отдельно проверяет эти случаи.

## Manual overrides

Для случаев, которые не поддаются обобщённому регексу, ввести файл `config/manual_overrides.json`:

```json
{
  "code": "socialnyy",
  "overrides": [
    {
      "find": "статьей 821 Налогового кодекса Республики Казахстан",
      "context_before": "доход работника, определенный",
      "replace_with_link": {
        "doc_id": "K2500000214",
        "anchor": "z12996"
      }
    }
  ]
}
```

Применяется новым скриптом `12_apply_overrides.py` после `13_cleanup_html.py`. Пока в этом этапе не вводим — собрать список после первого прогона исправлений.
