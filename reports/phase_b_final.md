## 4. Качество ретрива (small-to-big)

Резолв: query → e5(`query:`) → faiss top-k → родительская статья (uid) → полный текст.

### 4a. Тот же набор, что июнь (28 запросов по corpus-43) — дельта e5 vs старый MiniLM

| индекс | hit@1 | hit@3 | покрытие |
|---|---|---|---|
| **Июнь — MiniLM-384 (сданная база)** | 17/28 = **61 %** | 23/28 = **82 %** | 43 дока, 17 786 вект. |
| **Сейчас — e5-large, единый full-corpus** | 17/28 = **61 %** | 24/28 = **86 %** | **286 док, 36 366 вект.** |

**Дельта: hit@1 = (флэт 61 %), hit@3 +4 пп (82 %→86 %) — при 6× большем индексе.**
Прежний изолированный эксперимент «e5 только на 43» давал 68 %/89 %; снижение до 61 %/86 %
на едином корпусе — это **топ-дистракторы из новых законов** (напр. запрос «меры
пресечения» теперь тянет `Z990000353_` (правоохранит. служба); «мошенничество» — новый
`Z1600000011` выше УК-ст.190, которая остаётся в топ-3). Это честный трейд-офф единого
индекса на весь корпус, а не регресс модели: те же 28 запросов конкурируют против 243
новых законов. Полный разбор промахов — `reports/retrieval_eval.md`.

### 4b. 10 запросов по НОВЫМ законам (демо small-to-big)

**hit@1 8/10 (80 %), hit@3 9/10 (90 %).** Каждый показывает: попавший пассаж
(subchunk/article) → родительская статья → её ПОЛНЫЙ текст. Примеры:

- «охрана государственной границы РК» → `article` → **Z1300000070/ст.7** «Охрана
  Государственной границы» (713 симв).
- «отрасли, классы и виды страхования» → `subchunk` → **Z000000126_/ст.6** (3982 симв,
  n_subchunks=3) — сабчанк нашёл, отдан полный текст статьи.
- «субъекты управления госимуществом» → `subchunk` → **Z1100000413/ст.7** (1942 симв).
- «служба 112» → `article` → **Z1400000188/ст.6** «Единая дежурно-диспетчерская
  служба "112"».
- «госрегулирование рынка ценных бумаг» → `subchunk` → **Z030000461_/ст.3** (5160 симв, n_subchunks=4).

Промахи (честно): банки «правовой статус банка **второго уровня**» → сабчанк ст.132
(Переходные положения) вместо ст.7 (влияние «второго уровня» + семантика сабчанка);
«преднамеренное банкротство» top-1 = `koap/182` (релевантный cross-code про
адм. ответственность, но эталон ограничен целевым законом) → засчитан в hit@3.
Полностью — `reports/phase_b_newlaw_eval.md`.

## 5. BLOCK C (summary) — что заблокировано и как досбирать

`DEEPSEEK_API_KEY` отсутствовал во всех scope окружения этой машины и `.env` нет.
Задача заявляла ключ в env — фактически его не было. По §11 (ключи только из env)
ключ не выдумывается. Поэтому 664 крупнейших статьи (тело ≥ ~5031 симв) остались без
`summary` — в `build_passages` такая статья без summary **пропускается** как отдельный
пассаж, НО её сабчанки эмбеддятся, т.е. полный текст статьи остаётся в поиске. Индекс
функционален; отсутствует лишь «крупноблочное» summary-представление для этих 664.

**Досбор (когда ключ появится), ~45 мин суммарно:**
```
set DEEPSEEK_API_KEY=...              # только из env, в файлы/логи не писать
python scripts/vector/c_summarize.py --all --min-body 5030   # ~671 крупных, НЕ все 5303!
python embed_kit/embed.py --chunks derived/vector_layer/chunks.jsonl \
       --model embed_kit/model --out embed_kit/out --device cuda --batch 32   # ре-эмбед
python scripts/vector/g_build_index.py --from-vectors embed_kit/out/vectors.npy
python scripts/vector/i_retrieval_eval.py && python scripts/vector/phase_b_newlaw_eval.py
```
> ⚠️ **`--min-body 5030` обязателен.** `c_summarize --all` без порога суммаризирует ВСЕ
> 5303 parent без summary (цена ~$8, время ~4 ч), а цель — только ~671 крупных ≥5031
> (июньский порог; цена ~$1.1, ~35 мин). Старые 665 summary идемпотентно не пересчитываются.
> После досбора N пассажей вырастет 36 366 → ~37 030; `out/` нужно удалить (memmap
> привязан к старому N) и ре-эмбед пройдёт полностью (~9 мин на 2060 Super).
