# ADILETkz — структурирование НПА РК для adilet.kz

Публичный экспорт пайплайна обработки нормативных правовых актов (НПА)
Республики Казахстан: из «сырого» HTML с adilet.zan.kz → в **структурированный
HTML** + **JSON-карты якорей** + **JSONL-чанки** для отображения на adilet.kz и
для загрузки в векторную БД.

> Этот репозиторий — **курируемый срез** рабочего дерева: только готовые
> артефакты, канонические скрипты, карты, исходная разметка Анары и документация.
> Внутренние бэкапы, кэши, дампы и инфраструктурные конфиги сюда **не входят**.
> Внутренние IP/эндпоинты вычищены (в скриптах заменены на `localhost:9096`).

## Цель проекта

adilet.zan.kz отдаёт тексты НПА в виде плоского HTML без надёжной внутренней
навигации: ссылки «пункт 2 статьи 101-9» либо отсутствуют, либо ведут не туда,
либо разорваны на куски. Задача пайплайна:

1. **Построить иерархию** документа (разделы → главы → статьи → пункты →
   подпункты) и проставить стабильные якоря `#zN` на каждый заголовок статьи и
   узловой элемент.
2. **Связать внутренние ссылки**: каждая ссылочная фраза вида
   «пункт N статьи M» должна быть кликабельной и вести на правильный якорь
   внутри того же документа.
3. **Связать внешние ссылки**: упоминания других НПА («Предпринимательским
   кодексом РК», «Законом о госзакупках») разрешаются через **NPA-маппинг** в
   ссылку на корневой документ на adilet (без `#z`).
4. **Нарезать чанки** (`chunk_npa.py`) из канонического `_structured` для
   векторной БД.

## Пайплайн (порядок и роли скриптов)

Канонический порядок (детали — в `docs/RUNBOOK.md`):

| # | Скрипт                      | Роль |
|---|-----------------------------|------|
| 1 | `11_structure_html.py`      | строит иерархию (разделы/главы/статьи/пункты), нормализует разметку |
| 2 | `01_build_article_map.py`   | строит карту «статья → `#zN`» (`maps/article_map_<slug>.json`) |
| 3 | `07_add_subpoint_anchors.py`| добавляет якоря подпунктам (`maps/subpoint_map_<slug>.json`) |
| 4 | `02_fix_internal_links.py`  | оборачивает внутренние ссылки в `<a href="#zN">`; внешние — через NPA-маппинг |
| 5 | `68_link_canon.py`          | канонизирует href (self-ссылку → `#z`; меняется **только** href) |
| 6 | `71_fullspan_wrap.py`       | полно-спановое оборачивание: «пункт N статьи M» = один сплошной `<a>` |
| — | `audit_links_coverage.py`   | покрытие/висячие якоря |
| — | `67_independent_verify.py`  | независимая перепроверка |
| — | `64_final_verify.py`        | финальный гейт |
| — | `69_sixcheck_laws.py`       | 6-проверочный прогон для законов |
| — | `chunk_npa.py`              | нарезка JSONL-чанков из `_structured` |

**Правило неприкосновенности форм:** `_structured` — каноника для законов и
источник для канона ссылок; `_ready` синхронизируется **из** `_structured`,
**никогда наоборот**. Чанки строятся из `_structured`.

### `71_fullspan_wrap.py` — полно-спановое оборачивание

Двигает **границы** существующих `<a>`, **не меняя** ни `href`, ни видимый
текст (`get_text` инвариантен — это и есть гейт). Паттерны:

- **A (FORWARD):** `<a>пункт N</a> статьи M` → `<a>пункт N статьи M</a>`
- **B (BACKWARD):** `пункт N <a>статьи M</a>` → `<a>пункт N статьи M</a>`
  (жадно назад на **один** пункт + опциональный квалификатор
  часть/абзац/подпункт; стоп перед вторым пунктом)
- **M (MERGE):** два соседних `<a>` одной фразы → один (оставляем href пункта,
  href статьи отбрасываем, логируем)
- **C (RANGE):** `<a>N</a>-<a>M</a>` → `<a>N-M</a>`

Запуск: `python scripts/71_fullspan_wrap.py <slug...>` — Фаза 1 (инвентаризация,
read-only); `--apply` — Фаза 2 (с гейтами: sha `get_text` до==после; мультимножество
href для A/B неизменно; нет вложенных `<a>`; висячих `#z` = 0).

## Ключевые соглашения (KEY CONVENTIONS)

1. **Якоря `#zN`** ставятся на заголовок статьи и узловые элементы; `N` —
   стабильный числовой id. Карта «статья → `#zN`» лежит в
   `maps/article_map_<slug>.json`.
2. **Полно-спановое правило:** ссылочная фраза «пункт N статьи M» — это **один
   сплошной `<a>`**, а не «пункт N»-линк + плейн «статьи M». В границы **не**
   включаются хвосты «настоящего Кодекса/статьи», «Республики Казахстан»,
   «Закона». Две разные статьи-ссылки **не** сливаются.
3. **Внешние акты** разрешаются через NPA-маппинг и ведут на **корневой**
   документ на adilet **без `#z`** (мы не знаем чужой внутренней нумерации
   якорей).
4. **href-only канон:** `68_link_canon.py` и `71_fullspan_wrap.py` меняют
   только разметку ссылок; **видимый текст (`get_text`) не трогается** — это
   проверяется sha-гейтом.
5. **`data/source/*.html` — READ-ONLY.** Оригинальный сырой HTML никогда не
   редактируется. Не запускать полный структуризатор на уже замороженных
   (исправленных) кодексах.
6. **Формы:** `_structured` — каноника; `_ready` синкается из неё; чанки — из
   `_structured`.

### Открытый вопрос: якоря УК vs живой adilet

Якорь-карта Уголовного кодекса была **пересобрана**
(`article_map_ugolovniy_rebuilt.json`, 499 записей против 498 в исходной
`article_map_ugolovniy.json`). Нужно сверить нумерацию якорей `#zN` с тем, что
реально отдаёт живой adilet для УК, прежде чем считать УК-ссылки финальными.

### Модель деплоя (на обсуждение)

Два варианта выкладки на adilet.kz:
- **(a)** заменить страницы НПА на наши `_ready.html` (полный контроль над
  навигацией и якорями), либо
- **(b)** оставить существующие страницы adilet и до-вешивать/чинить ссылки
  поверх.

Вариант влияет на трактовку внешних ссылок и на необходимость сверки якорей с
живым adilet (см. открытый вопрос по УК).

## NPA-маппинг (разрешение внешних ссылок)

- **Файл:** `maps/npa_mapping.json` (287 записей).
- **Схема:** плоский словарь `{ "<фраза-название акта>": "<adilet doc_id>" }`.
  Ключ — то, как акт упоминается в тексте (в нужном падеже), значение — НГР.
  Пример:
  ```json
  { "Предпринимательским кодексом Республики Казахстан": "K1500000375" }
  ```
- **`maps/codes.json`** — реестр обрабатываемых документов (slug → doc_id, плюс
  `_deprecated_remaps`, напр. `K1700000120 → K2500000214` для Налогового).
- **`maps/manual_overrides.json`** — ручные точечные правки разрешения ссылок.
- **`maps/article_map_<slug>.json`** — карта «статья → `#zN`» внутри документа.
- **`maps/subpoint_map_<slug>.json`** — карта якорей подпунктов.

## Известные проблемы / бэклог

- **УК-якоря** — сверить `article_map_ugolovniy_rebuilt.json` с живым adilet
  (см. открытый вопрос выше).
- **Full-span** применён как **пилот** только к ГК (обе части); раскатать тем же
  `71_fullspan_wrap.py` на УПК и остальные кодексы.
- **`grazhdanskiy_osob`** не имеет собственной article-map (обслуживается общей
  картой ГК) — проверить покрытие ссылок в Особенной части.
- **Формальная приёмка Анары** по документам, кроме ГК, — уточнить и отметить в
  таблице статусов.
- **Модель деплоя** (a/b) не зафиксирована — влияет на трактовку внешних ссылок.

## Безопасность экспорта

- Внутренний рабочий IP/эндпоинт в скриптах заменён на `localhost:9096`; по
  всему срезу прогнан сквозной анти-IP свип (0 совпадений внутреннего адреса).
- Не включены: `.env`, ключи/сертификаты (`*.key`, `*.pem`, …), VPN/RDP/Forti
  конфиги, кэши/дампы/бэкапы, бинарные docx Анары (вместо них — текстовые
  выгрузки в `source/`).
- PII (ИИН/ФИО/номера дел) в срезе не обнаружено.
