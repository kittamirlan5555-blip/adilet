# План фикса zNh / G6 (Фаза 3 — ОТЛОЖЕНО НА РЕВЬЮ)

Автономный заход: диагностировал первопричину, написал фикс, прогнал dry-run,
ПОПРОБОВАЛ применить — `verify --all` дал регресс (67_independent), поэтому
**ОТКАТИЛ** и оставляю план на ревью (как предписано: «применяй только если verify
остаётся GREEN с 0 регресса»). Корпус — в исходном GREEN-состоянии, ничего не
закоммичено из правок final/.

## 1. Первопричина — премиса про 11_structure НЕВЕРНА

`11_structure_html.py` **НЕ инжектит zNh**: не читает `article_map`, не зовёт 01/07,
функция `get_anchor_id()` только ИЗВЛЕКАЕТ существующий якорь (id / вложенный
`<a name|id>`). Синтетический `zNh` создаёт `01_build_article_map` (Способ 4/5 —
для заголовка статьи БЕЗ собственного якоря) и инжектит `07_add_subpoint_anchors`
(в `_ready`, до 11). `zNh` есть в ОБЕИХ формах (проверено: konstsud `z23h` и в
`_ready`, и в `_structured`).

**Настоящая причина (§9, схема якорей adilet ≠ нашей выгрузки):**
adilet-исходник ссылается на свой `#zN` (у adilet `zN` = статья N). В НАШЕЙ выгрузке
`zN` нередко садится на **«Примечание ИЗПИ/РЦПИ»** (не на статью), а заголовок
статьи получает синтетический `zNh`. Поэтому исходные self-ссылки `«статьёй N» → #zN`
у нас **ведут на примечание, а не на статью**. `68_link_canon` канонизирует
само-ссылки в каждой форме НЕЗАВИСИМО → формы могут разойтись (G6).

## 3. Почему простой фикс НЕБЕЗОПАСЕН (что сломалось)

`79 --apply` на всех 43 → `verify --all` **FAIL: 67_independent** (mismatch=1):
> `[trudovoy] #z32 заявл.ст.32 → резолв ст.124-2`

Причина: **`article_map_trudovoy[32] = z32`, но `z32` в нашей выгрузке = статья 124-2**,
а НЕ статья 32. То есть в карте некоторых ПРИНЯТЫХ доков есть НЕВЕРНЫЕ записи.
`79` слепо доверяет `article_map` → переподвесил «статьёй 32» на `z32` (=124-2) →
создал мислинк. **Слепой корпусный `79` распространяет битые записи карты.**

Вывод: 79 безопасен для batch-доков (карты собраны свежо и корректно), но НЕ
корпусно. Полный ре-прогон (пересборка карт из source) — ЗАПРЕЩЁН (снесёт ручные
правки принятых доков).

## 4. Рекомендуемый фикс (на ревью)

**Шаг A — guard в `79_canon_self_anchor`:** репойнтить `«статья N» → article_map[N]`
ТОЛЬКО ЕСЛИ элемент по `article_map[N]` действительно заголовок статьи N (текст
рядом начинается с «Статья N.»). Тогда:
- genuine note-мислинки (nalog z189h, ugolovniy z45h, …) — чинятся (цель = «Статья N»);
- битый кейс trudovoy[32]→z32(=124-2) — ПРОПУСКАЕТСЯ (z32 не у «Статья 32»), мислинк
  не создаётся.

**Шаг B — dry-run guarded-79 на 43:** разделить на (1) чинимые note-мислинки,
(2) пропущенные из-за битой карты — выписать список битых записей карты.

**Шаг C — ручной аудит битых записей карты** (trudovoy[32] и др., найденные в B):
это data-баги карт принятых доков; чинить точечно (карта + при необходимости якорь),
text-invariant, по одному, с verify.

**Шаг D:** guarded-79 --apply + verify --all GREEN → коммит. Иначе — снова стоп.

**Профилактика (чтобы не повторялось):** сделать guarded-79 ШТАТНЫМ шагом пайплайна
после `68_link_canon` (сейчас он применяется реактивно по флагу G6). Тогда новые
доки авто-канонизируют само-ссылки на валидный якорь статьи.
