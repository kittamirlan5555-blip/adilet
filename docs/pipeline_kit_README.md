# law_kit — самодостаточный кит обработки законов/кодексов РК

Превращает «сырой» HTML нормативного акта с `adilet.zan.kz` в:
структурированный HTML (вложенность раздел→глава→статья) → внутренние гиперссылки →
JSON-дерево + JSONL-чанки, с аудитом корректности.

Пошаговая инструкция для новичка — в **`RUNBOOK.md`**.

## Требования
- Python 3.9+
- `pip install beautifulsoup4` (единственная внешняя зависимость; всё остальное — стандартная библиотека)

## Структура
```
law_kit/
  scripts/      8 переиспользуемых скриптов (см. ниже)
  config/
    codes.json  реестр: ключ → {doc_id (NGR), title}
  data/         пустой скелет (заполняется при обработке)
    source/     входные HTML с adilet (read-only источник правды)
    final/      {ключ}_structured.html — структура + ссылки
    maps/       article_map_* / subpoint_map_* (служебные JSON)
    tree/        {ключ}.json — дерево статей
    chunks/      {ключ}.jsonl — чанки для поиска/RAG
    reports/     отчёты аудита и расстановки ссылок
  RUNBOOK.md    пошаговый прогон одного закона
  README.md     этот файл
```

## Скрипты (что за что)

**`11_structure_html.py`** — *структуризатор.* Берёт сырой HTML статьи (`<article>` с наибольшим объёмом текста), распознаёт заголовки (ЧАСТЬ / РАЗДЕЛ / ПОДРАЗДЕЛ / ГЛАВА / ПАРАГРАФ / ПОДГЛАВА / СТАТЬЯ, в т.ч. стиль `<p><b>Статья N</b></p>`) и строит вложенную иерархию `<div data-type=… data-number=…>`. Сохраняет head/навигацию. CLI: `--input --output`. Это основа всего пайплайна; результат — `_structured.html`.

**`01_build_article_map.py`** — *карта «статья → якорь».* Сканирует HTML и сопоставляет каждому номеру статьи её anchor-id (`<a name="zN">`, `<h3 id="zN">` или `<p><b>Статья N`). Если у заголовка нет реального якоря — назначает синтетический `z{N}h`. Результат — JSON `{ "N": "zN", ... }`, который нужен скриптам 07 и 02. CLI: `--input --output`.

**`07_add_subpoint_anchors.py`** — *инжектор якорей.* (а) Вставляет реальные `<a id="z{N}h">` в заголовки статей, у которых якоря не было (по синтетическим из карты 01) — без этого ссылки «статья N» оказались бы битыми; (б) проставляет id подпунктам/пунктам (`1)`, `2.` → `z{ст}_{пункт}_{подпункт}`) и строит карту подпунктов для точной адресации. CLI: `--input --output --map [--subpoint-map-output]`.

**`02_fix_internal_links.py`** — *внутренние ссылки.* Находит в тексте отсылки («статья N настоящего Кодекса», «пунктом N статьи M», «подпунктом K) пункта N» и десятки иных форм) и оборачивает их в `<a href="{base_url}/rus/docs/{doc_id}#{якорь}">`, не трогая текст внутри уже существующих ссылок, заголовков статей и сносок. Требует карту статей (01) и желательно карту подпунктов (07). CLI: `--input --map --doc-id --output --report [--subpoint-map]`.

**`audit_links_coverage.py`** — *аудит покрытия и корректности (read-only).* PART 1: считает покрытие гиперссылок (cov_lit/cov_content/cov_real) и разбивает «нелинкованные» отсылки по типам. PART 2: для каждой внутренней `<a href="#zK">` сверяет заявленный в тексте номер статьи с тем, куда реально ведёт якорь, и классифицирует: OK / WRONG_TARGET / WRONG_SUB / BROKEN / SELF_WRONG / NONART; плюс сверка внешних NGR с именем акта. Читает `config/codes.json`, `data/final/*_structured.html`, `data/source/*.html`. Запуск без аргументов; обходит список кодов в `main()` (для нового закона ключ добавляется в `order`).

**`chunk_npa.py`** — *чанкер.* Читает `_structured.html` и строит (1) JSON-дерево «статья → пункт → подпункт» в `data/tree/` и (2) JSONL-чанки в `data/chunks/`, где строка = пункт со всеми продолжениями и подпунктами. Каждому чанку даёт `id`, текст с шапкой `[КОД | Статья N. Заголовок | пункт K]` и `meta` (code, doc_id, article, hier_id вида `КОДRxGySTnPk`, статус active/repealed). Крупные статьи-словари режет по подпунктам. CLI: `{ключ}` | `--all` | `--test`. Берёт коды из `codes.json` (новый закон подхватывается автоматически после шага 2).

**`29_diff_ready_structured.py`** — *диагностика дивергенции.* Сравнивает упорядоченную последовательность ссылок в двух формах файла — `_ready` и `_structured` — и показывает расхождения (retarget / only_ready / only_struct). Нужен только когда ведутся ОБЕ формы; `--reconcile` подтягивает `_ready` к канону `_structured`. Импортирует `audit_links_coverage.py` (за `SELF_DOC`). Для одного закона в минимальном маршруте (только `_structured`) — не требуется.

**`67_independent_verify.py`** — *независимый верификатор (2-й метод).* Полностью независим от аудита: сам строит карту id→номер статьи (по `<h3 id>` и по data-number предка) и проверяет каждую внутреннюю ссылку «статья N» через эту карту, отдельно сверяя внешние NGR с именем акта. Учитывает якоря-закладки начала статьи (ИЗПИ/РЦПИ-границы) форвард-сканом сырого HTML. Цель — подтвердить корректность вторым, ортогональным механизмом. Запуск без аргументов; для нового закона ключ добавляется в встроенные `CODES`/`SELF`.

**`config/codes.json`** — реестр актов: `ключ → {doc_id, title}`. `doc_id` (NGR) берётся из URL adilet и используется всеми скриптами как идентификатор документа в ссылках.

## Поток данных (один закон)
```
source/{ключ}.html
   └─11─▶ final/{ключ}_structured.html ──01─▶ maps/article_map_{ключ}.json
                                        ──07─▶ (инжекция якорей) + maps/subpoint_map_{ключ}.json
                                        ──02─▶ final/{ключ}_structured.html (+ ссылки)
                                        ──chunk_npa─▶ tree/{ключ}.json + chunks/{ключ}.jsonl
   проверка: audit_links_coverage  +  67_independent_verify
```
