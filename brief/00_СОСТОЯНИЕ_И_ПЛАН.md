_Собрано из: переписки с Анарой (10.03–19.05.2026), её Word-файлов (9 кодексов), Excel (ТК, УК) и текущего состояния проекта._

## 1. Что это за проект (коротко, чтобы не плыть)

Ты берёшь сырой HTML кодексов с adilet.zan.kz и скриптом проставляешь гиперссылки:
- **внутренние** — ссылка «статья 99 настоящего Кодекса» → якорь на эту статью внутри файла;
- **внешние** — ссылка «в соответствии с Налоговым кодексом» → на другой НПА.

Анара (проверяющий эксперт) сверяет готовые HTML и кидает замечания: Word-файлы, Excel, скрины, текст в телеге. ЕК (заказчик) торопит, цель — **10 кодексов**.

## 3. Правила Анары — что считается «правильно» (полный свод)

Это извлечено из всех источников, включая Excel ТК/УК, где видны точные формулировки действий:

1. **Внутренняя ссылка** (статья/пункт/подпункт «настоящего Кодекса») → кликабельный якорь + переход + **подсветка цели другим цветом после перехода** (формулировка Анары: _«принято, дополнить после перехода выделить другим цветом»_).
2. **Внешняя ссылка** (другой кодекс/закон РК) → ссылка на внешний НПА.
3. **Сноски** (`в сносках`) → **ссылок НЕ делать / убрать** (правило ЕК ещё с 11.03: _«по внутренним ссылки на сноски не нужны»_).
4. **Примечания** (`в примечании`) → **ссылок НЕ делать / убрать**.
5. **НЕ перелинковывать**: кликабельным делается **только конкретный элемент**, на который указывает ссылка, а не весь абзац / несколько пунктов. Дословно: _«тут нужно было только в одном пункте статью выделить и всё»_.
6. **Заголовки статей** — жирный чёрный, **единообразно по всему файлу** (ст. 115 «сбилась» — починить).
7. Утратившие силу законы — **не линковать** (13.05).
8. **Не цеплять контекстные слова** (14.04): при ссылке вида «… 2-1 настоящей статьи» кликабельным должно быть **только «2-1»**, а не слова «настоящей статьи». Это частый источник over-linking.
9. **Единообразие слов «пункт/подпункт»** (02.04): по всему файлу одинаково — либо само слово «пункт/подпункт» синее+кликабельное вместе с цифрой, либо кликабельны **только цифры**. Не вперемешку.

## 6. План (3 фазы)

### Фаза 0 — единый список ✅ ГОТОВО
`01_ЕДИНЫЙ_ЧЕКЛИСТ_АНАРЫ.md` собран. Это и есть твой «выписать все замечания в одно место».

### Фаза 1 — стабилизировать скрипт (один раз, до поштучной сверки)
Прежде чем долбить вручную — закрыть системные баги, чтобы не править одно и то же руками 400 раз:
1. **Анти-over-linking**: линковать только целевой элемент ссылки, не весь блок. Это главный регресс 19.05.
2. **Сноски/примечания**: правило «не линковать внутри `<сноска>`/`<примечание>`» (по словам — массово в УК и ТК).
3. **Жирный заголовков статей**: единый класс/стиль на все `data-type="статья"`.
4. **Подсветка цели после перехода** (`:target { background: … }` или JS) — Анара просит во всех «принято, выделить другим цветом».
5. **УПК прогнать заново** с нуля исходником `data/source/upk.html`.

### Фаза 2 — поштучная сверка через Claude Code (твоя основная идея)
По одному кодексу за раз. Для каждого пункта чеклиста: **проверить, сделано ли → если нет, сделать → отметить `[x]`**. Скрипт берёт ~95%, остаток (~5%) — руками. Используй шаблон `claude_code_prompt_шаблон.md`.

**Порядок** (от быстрых побед к тяжёлым, чтобы показывать ЕК прогресс):
`Бюджетный → АППК → Экологический → Земельный → КоАП → Трудовой → Социальный → Предпринимательский → Гражданский+Налоговый (добивки) → УК → УПК (заново)`.

### Фаза 3 — самопроверка перед отправкой
Прямое требование Анары 19.05: _«перед тем как мне снова кодексы отправлять, сами проверьте прям по Word, который я скидываю»_. Перед каждой отправкой — прогон чеклиста по конкретному кодексу, ни одного `[ ]` не осталось.

## 7. Как не упереться в лимит

Этот разбор разбит на durable-файлы на диске. Если лимит кончится — подожди и напиши **«продолжай»**: я продолжу с того места (следующий шаг — Фаза 1, правки скрипта, по одному модулю за ответ). Поштучную сверку (Фаза 2) лучше гонять в Claude Code локально — там длинные HTML не жрут твой чат-лимит.
